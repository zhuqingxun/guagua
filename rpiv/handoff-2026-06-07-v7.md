## TL;DR

- ⛔ **核心任务未完成**：鸭子 PS4 蓝牙手柄重连，卡在 btmon 确诊的 `Authentication Failure (0x05)`，回连时 host 提供密钥后认证失败、连上即断

## 下一步动作（新会话主动执行）

1. **先确认哪个物理手柄是用户的**（advisor 的决定性实验，做任何系统改动前必做）：
   - 让用户**完全关闭手柄**（长按 PS ~10 秒到灯**全灭**）
   - `ssh duck` 跑 `bluetoothctl scan on` ~15 秒，列出所有 `Wireless Controller` MAC + 各自 RSSI
   - **手柄关了还显示的 MAC = 不是用户的**（邻居的还开着）
   - 让用户开手柄进配对模式，再 scan：**新出现的 + RSSI 最强（-40~-55，鸭子旁边）的 = 用户真手柄**；邻居的 RSSI -70+
   - **重点验证假设：用户真手柄是不是 `81:FC:F1`**（Pi 上唯一成功 bond 的那个）
2. **确认真 MAC 后**：用它走配对，并**抓【配对过程】的 btmon**（IO Capability → Simple Pairing Complete → **Link Key Notification**）——本会话只抓过【回连】btmon，从没抓过【配对】btmon。这能区分"两个设备/认错目标" vs "设备不持久化密钥"
3. **若真手柄是 81:FC:F1**：它已有成功 bond，可能短按 PS 直接回连成功（或干净 fresh-pair）→ **整个 saga 解决，证明用户判断对（系统没坏、手柄没问题，是我一直在认证错误的设备）**
4. 手柄通了之后：验证 js0 + jstest 有真实输入 → 才算 Task#1 完成；再继续 Task#4（下发 Runtime 到鸭子）+ Task#5（手柄走路验证换的 right_knee 舵机）

## 被否定的假设清单（⛔ 别重走，全部已验证否定或不解决）

| 假设 | 否定证据 |
