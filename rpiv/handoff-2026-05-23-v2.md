## 教训锚点 (本次会话沉淀, 已写入 docs/duck-workspace-state.md §6)

1. **vendor 接手时, 新模式 (LLM/voice) 必须端到端验证至物理动作, 不能只看 mcp tool 调用响应**:
   爱折腾自己 demo 应该全程 PS4 手柄, 从未真正 LLM 模式端到端跑通. 5 个 bug 全部在 LLM 模式才暴露 (PS4 模式都不触发).

2. **vendor patch 必须 grep 调用方下游消费方式, 不能只看构造函数**:
   `6f93be8` PS4 patch 我只看了 line 125 PS4Controller() 构造, 没看 line 300 merge_commands 怎么用返回值, 引入 stub 数据结构不匹配 regression.

3. **systemd 下 stdout 是 block-buffered socket (8KB flush)**:
   `print()` 默认 line-buffered 仅当 stdout 是 terminal, 进 systemd journal 是 socket → block buffered → init 阶段 print 全部假死. PYTHONUNBUFFERED=1 是 systemd 跑 Python 服务的标配.

4. **"耳朵能动 vs 走路不行" = paused 守卫前后代码的诊断特征**:
   line 463 antennas 在 paused 守卫**前**, line 476 if self.paused: continue **后**才是 RL/写舵机. 用户给的物理观察精确锁定 paused=True 假设, 比所有日志诊断都快.

5. **"二次失败硬重置"实际触发场景**: 修 PS4 stub crash → PYTHONUNBUFFERED 假死 → paused 翻烧饼, 3 次"修复" 串联. 当时应该早点 advisor 检查, 不要顺手打补丁. (本会话第 2 次修 PYTHONUNBUFFERED 时调用了 advisor, 反馈有效.)

6. **ws 协议双向**: mcp-openduck 的 `ws_handler` 接受 client 发的 `{"cmd": "duck_xxx", "args": {...}}` JSON dispatch 到 COMMAND_MAP. 这是绕过 LLM 直接测 MCP 工具的关键能力, 调试时极有用 (scripts/duck-ws-unpause-experiment.py).

7. **PS4 vs Xbox 按键命名**: PS4 物理 X 键 (底部叉) = Xbox A 键 = 代码里 `buttons.A`. 用户记忆"按 X 解锁"完全正确, 只是命名空间转换.
