## 经验沉淀（跨会话价值）

1. **pygame.joystick.quit() + init() 不重新枚举设备** — pygame 2.6 + SDL 2.28 行为, 设备列表第一次 init 时锁定. 热插拔必须用 `pygame.event.get()` + `JOYDEVICEADDED/REMOVED` 事件机制, 不是 quit/init 循环. (今天 v1 实验脚本踩坑后修正到 v2)
2. **DS4 不允许 host 主动 connect** — `bluetoothctl connect <DS4>` 报 `br-connection-create-socket`, DS4 必须设备端按 PS 键发起广播. 这是 DS4 固件特性, 不是配置 bug. 任何 DS4 reconnect 流程必须依赖设备端操作
3. **Pi 3B+ soft thermal limit 阈值 = 60°C** (不是 80°C) — 比想象的低. 长时间满载 50Hz RL loop + ONNX 推理容易触发. 但用户散热好 = 该 Pi 可能配置不同阈值, 需要查 `/boot/config.txt temp_soft_limit`
4. **Pi DVFS 自适应电压跟 throttle 联动** — 高频满载 1.3125V, 降频后掉到 1.2V 区. 不要凭电压瞬时低判电池不足, 必须同时看 throttle bit 3 + 真实电池/电源供电链路
5. **vendor 新模式必须端到端验证至物理动作** (5/23 教训, 今天可能在 walk 场景重演) — 5/22 PS4 模式 + 5/23 LLM 模式都只测了短动作, **持续 walk 5+ 秒可能是 5/24 14:07 第一次**. 这种"测试覆盖不足"是反复踩坑点

## 教训锚点

- **2026-05-24 1.2313V 误判事件**: stop 服务前看到 volt=1.2313V + throttle=0x80008, 凭"电池供电+电压低"快速归因"电池不足". 后被用户告知"接的是稳压电源" 立即翻车. 正解 = Pi DVFS 自适应电压, 跟 throttle 降频联动, 不是电池信号. **教训**: 任何"电压低"判定都要先排除 DVFS, 看 throttle 状态 + 看真实电池/电源链路
- **2026-05-24 散热假设错位事件**: 凭"throttle bit 3 触发"快速归因"散热不足", 被用户直接否定"散热非常好". 正解 = 散热好 ≠ Pi config 阈值高, 也 ≠ 当前实际不会过热. 需要查 config.txt + 持续监控温度趋势. **教训**: 用户的物理观察是 ground truth (硬件层), Claude 看的是软件层信号 (CPU temp / throttle), 两者要协同, 不能凭一方下结论
