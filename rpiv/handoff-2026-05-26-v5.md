## 经验沉淀 (跨会话价值)

1. **PS4Controller 双 thread pygame.event.get() destructive read bug** (vendor 6th bug): commands_worker @ ≥20Hz drain SDL event queue 抢先, main loop @ ~2Hz pump 永远拿不到 REMOVED 事件。修复模式: 两边各自处理 REMOVED + idempotent detach + commands_worker raise pygame.error 让 except 同步生效
2. **MCPController.commands[:] return Python list** + PS4Controller __init__ list 初值 → merge_commands `m_last + p_last` = list concat (14 维) 而非 element-wise add (7 维)。这是 numpy + Python list 混用导致的隐蔽 dim concat bug, 修复模式: 任何下游做 `+` element-wise add 假设的数据流, 上游必须强类型 (ndarray) 防 list 漂移
3. **walk stall 真凶不是限流** (本会话实测打脸 5/24 推断): 没实测的根因 = 推断 ≠ ground truth. 教训: 用户实测电流 1A 比文档 "M3 25A" 三档限流真值更优先
4. **ONNX 模型 input dim 用 onnxruntime.InferenceSession get_inputs() 拿真值**, 不要凭 ONNX 文档或 vendor 注释:
   ```python
   import onnxruntime as ort
   s = ort.InferenceSession(p)
   for inp in s.get_inputs(): print(inp.name, inp.shape, inp.type)
   ```
5. **/dev/input/jsX gone ≠ SDL 立即知道**: BT disconnect 后 evdev js device 立刻消失, 但 SDL pygame.event.get() 必须被 pump 才能拿到 JOYDEVICEREMOVED 事件。多 thread pump 时, 谁先拿谁消费 (destructive)
