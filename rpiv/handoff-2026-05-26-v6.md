## 元规则更新 (本会话沉淀)

### 1. 用户物理操作降到最低 (新沉淀到 memory)

**已写入** `~/.claude/projects/D--CODE-guagua/memory/feedback_minimize_physical_operations.md`:
- 禁止让用户做"手感对比""触觉判断""5 对舵机分别摆动找差异"这种需要 know-how 的高负担任务
- 允许单次确定性物理动作 (按一下/保持不动/把鸭子放地上)
- 优先脚本化采样 + AI 看 output 决策, 用户只做最小输入
- ssh 命令默认我自己 Bash tool 跑, 不让用户在他自己终端跑 (除非脚本需要 stdin 互动)

### 2. PowerShell ssh stdout buffering 行为

- PowerShell 7.6.1 + Windows OpenSSH client `ssh duck "cmd"` 默认非 TTY → **整个会话 stdout buffer 到结束才 flush**
- `ssh -t duck "cmd"` 加 `-t` 强制 TTY 也不一定根治 (本会话 v2 加 -t 仍出现同样 buffering)
- 真正治本: **脚本 self-paced 设计 (不靠用户实时看 stdout 节奏)** 或 **我用 Bash tool 自己跑 ssh** (跳过用户终端)
- 教训: 设计 verify 方案前问 "用户需要实时看 stdout 反应吗?" 不需要 → 我自己 Bash tool ssh

### 3. 嗡嗡声 = 力矩饱和 (硬件诊断模式)

- ST3215 持续嗡嗡 = 收到 goal_position 但 hold 不到 → 持续 PWM → 力矩接近饱和
- 三选一: (a) 机械卡阻 (b) 过热降扭 (c) RL 命令变化太快超出舵机响应
- 诊断捷径: walk 后立即 stop service + 跑 pypot `get_present_temperature/load/current` → 左右配对对比 ΔT
- 关键: timing 紧凑 (walk → done → ssh stop service → 读 temp 全程 ≤ 10 秒), 温度散热前抓住 walk 时分布

### 4. 假设 H 否定模式 (joints_offsets sign convention)

- vendor `init_pos` 字典里 hip 左右镜像 (-/+) + knee/ankle 左右同号
- 任何 joints_offsets 配置需要按这个 sign convention 检查左右是否对称, 不是数值对称
- ncnynl 6737 教程帮助 = 否定 A 的子分支 + 引出 soft_offsets 路径, 不是直接答案

### 5. rustypot Python binding 局限

- `rustypot.FeetechController` 只暴露 6 个 method: `disable_torque / freeze / get_current_speed / get_present_position / set_new_kps / set_new_target`
- **没有 read_present_load / read_present_temperature / read_present_current**
- 想读这些必须用 pypot (但 pypot 跟 rustypot 不能并发开同一串口)
- 工作流: walk 完立即 stop service (释放串口) + 跑 pypot snapshot
