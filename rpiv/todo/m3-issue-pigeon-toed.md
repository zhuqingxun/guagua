## 现象

5/8 晚上首次跑通行走测试 (教程 6757) 后观察到：**一只脚明显内八字**（具体是左脚还是右脚待用户确认 + 拍照记录）。其余步态主体功能正常，所以并非 ONNX 推理或 50Hz 控制循环失效，而是机械层 / 标定层的问题。

## 不立即处理（用户决策，2026-05-09）

按 CLAUDE.md 的「先熟悉再变更」原则（这一条同时也是卖家在 5/7 18:35 的明确建议），先不动这个问题：
- 用户当前对硬件还是小白阶段，先把 S0 路径走完（联网 / web 控制 / 小智语音）再回头处理
- 调姿态可能涉及拆装舵机 / 改 `duck_config.json` 关节偏移 / 重新对齐托盘标记 → 风险大于收益
- 跑得起来 ≠ 跑得正，但 S0 阶段验收点是"跑起来"，不是"跑得直"

## 候选根因（不预设，留给后续诊断）

按可能性从高到低排列，处理时要逐项验证而不是直接下手：

1. **舵机零位 / 关节偏移没标定到位**
   - 整机出厂时卖家说"会根据每台做独立参数优化"（5/3 23:42）
   - 可能在快递运输中舵机轻微移位
   - 检查方法：看 `duck_config.json` 里 hip / ankle 关节的 offset，对照出厂值
   - 修复路径：跑教程 6744「设置关节偏移」+ 6737「舵机配置」（注意先做标记 = 卖家 5/7 18:48 的建议）

2. **机械层装配偏差**
   - 黄色三角连接器 / 髋关节螺丝没拧紧 → 舵机有空程
   - 3D 打印件公差累积
   - 检查方法：手动扭动腿部，看哪一段有"虚位"
   - 修复路径：拆开后盖看连接 + 拧紧

3. **物理层不可逆差异（最坏情况）**
   - 爱折腾改 STL 件时引入了不对称（卖家承认"直接改某些件，没重建 3D 模型"，5/6 13:52）
   - 推理模型是基于上游官方原版训练的 ONNX，物理层不对称导致推理输出在某条腿表现失真
   - 修复路径：M2 阶段自己训一版，但门槛较高（PRD M2 决策门后才考虑）

4. **IMU 偏移**
   - BNO055 没校准到位 → 控制器误判机身倾斜 → 一侧腿过度补偿
   - 检查方法：跑教程 6743「IMU 配置」中的标定脚本
