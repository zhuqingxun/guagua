# 家庭陪伴机器人选型与实施路线图

## 文档元信息
- **创建时间**: 2026-05-01
- **项目目标**: 构建家庭自主陪伴机器人
- **核心定位**: 物理交互 + 情感交互双重能力
- **预算结构**: 阶段A(学习期)1万元 / 阶段B(产品期)5万元
- **时间投入**: 每周10小时
- **技术路线**: sim2real强化学习 + VLA多模态交互

---

## 一、项目背景与战略定位

### 1.1 核心目标拆解

**短期目标(阶段A,M0-M6)**
- 走通完整 sim2real 强化学习工程链路
- 实现双足机器人在地板环境下的自主行走
- 掌握 MuJoCo 仿真 → PPO训练 → ONNX部署全栈技能

**中期目标(阶段B,M6-M18)**
- 在物理交互维度:可触摸、可跟随、动态平衡、抗推搡
- 在情感交互维度:视觉识别、语音对话、表情表达、记忆系统
- 整合 VLA(Vision-Language-Action)模型实现具身智能

**长期愿景**
- 成为家庭场景中真正意义上的"陪伴成员"
- 支持儿童教育、老人监护、家庭助手等多角色切换
- 为后续商业化/量产探路

### 1.2 形态选择的战略决策

**市场形态分类(基于 CES 2026 观察)**
1. 小尺寸人形机器人(<1米):主打家庭陪伴,目标受众为有娃家庭、科技爱好者
2. 四足机器狗:主打全地形适配,偏向户外探索、安防、负重
3. 桌面陪伴机器人:主打情感交互,弱化运动能力
4. IP衍生机器人:依托IP快速获客,娱乐属性强

**最终选型:小尺寸双足人形**
- **物理尺寸**: 40-50cm 高度(参考 Open Duck Mini / 深庭纪 Rovar X3)
- **核心理由**:
  - 尺寸安全不威胁,易被家庭成员接受
  - 双足形态的运动复杂度高,技术深度足够支撑长期学习
  - 拟人化外观更容易建立情感联结
  - 成本可控,适合个人/小团队开发

**与其他备选方案的对比**

| 方案 | 优势 | 劣势 | 是否采纳 |
|---|---|---|---|
| Unitree Go2 EDU(四足) | 成熟平台,户外能力强 | 与"陪伴"定位不符,情感属性弱 | ❌ 不采纳 |
| 桌面型(Ropet/Looi类) | 情感交互成熟,低风险 | 无真实运动能力,技术挑战小 | ❌ 不采纳 |
| 大尺寸人形(80cm+) | 功能空间大 | 成本>10万,超出预算 | ❌ 不采纳 |
| 小尺寸双足(Open Duck Mini架构) | 技术挑战适中,成本可控,可扩展性强 | 需自研,风险存在 | ✅ 采纳 |

## 二、技术架构设计

### 2.1 整体系统架构

```

                              ↕ 4G/WiFi

│  │ • 语音识别/合成(Whisper + Edge TTS)               │   │

└─────────────────────────────────────────────────────────┘
                              ↕ 串口/I2C
┌─────────────────────────────────────────────────────────┐
│                      执行层                               │
│  • 关节舵机(Feetech STS3215 ×14 → 部分升级准直驱)        │
│  • IMU(BNO055)                                           │
│  • 足底力传感器(FSR ×4)                                  │
│  • 表情显示(双圆形IPS屏 + 主屏)                          │
│  • 麦克风阵列 + 扬声器                                   │
└─────────────────────────────────────────────────────────┘
```

### 2.2 关键技术栈

**仿真与训练**
- 仿真引擎: MuJoCo Playground
- 机器人建模: URDF(从 Onshape CAD 导出)
- 参考运动生成: Open_Duck_reference_motion_generator(基于 Placo IK)
- RL算法: PPO with imitation reward
- 训练框架: Isaac Gym(备选) / MuJoCo(主)
- 实验管理: Hydra + Weights & Biases

**板载推理**
- 运动策略: ONNX Runtime(CPU推理即可,30-50Hz控制频率)
- VLA推理: TensorRT(GPU加速)
- 候选VLA模型: OpenVLA / RT-2 微调 / 自训小模型

**多模态交互**
- 语音识别: Whisper(边缘部署)
- 语音合成: Edge TTS / PaddleSpeech
- 视觉感知: Orbbec SDK → 点云处理 → 目标检测/跟踪
- LLM对话: Claude API(主) / 阿里百炼 Qwen(备)
- 表情系统: 自定义动画引擎(基于状态机)

**数据与记忆**
- 短期记忆: 板载 SQLite
- 长期记忆: Qdrant(向量) + Neo4j(图谱)
- 数据采集: ROS2 bag(所有传感器数据落盘)

### 3.2 关键硬件决策说明

#### 决策点1: 主控为何选 Jetson Orin Nano 而非 RDK X5?

| 对比维度 | RDK X5(地瓜 BPU) | Jetson Orin Nano 8GB | 决策依据 |
|---|---|---|---|
| 价格 | ~1500元 | ~3500元 | 多投入2000元 |
| Open Duck Mini 适配 | ✅ 有完整中文教程(Frank Fu验证) | ⚠️ 需自己适配 | 学习成本 RDK 更低 |
| 阶段B 生态对齐 | ❌ BPU生态封闭 | ✅ 与 NVIDIA Isaac/Omniverse 完整对齐 | **关键长期优势** |
| 与已有规划一致性 | ❌ 与 Go2+Orin NX 路线脱节 | ✅ 工具链一致,技能可迁移 | 长期资产价值 |
| VLA 模型部署 | ⚠️ 生态支持弱 | ✅ TensorRT 原生支持 | 阶段B核心能力 |

**最终决策**: **选 Jetson Orin Nano**
**核心理由**:
- 阶段A的额外2000元投入,在阶段B时避免主控更换带来的3-5周重新适配成本
- 与长期家庭机器人技术栈(NVIDIA 生态)完全对齐
- 即使阶段A需要1-2周额外适配工作,摊到每周10小时的投入里可接受

**风险缓解**:
- 预留 M0-M1(前两周)专门用于 Orin Nano 环境搭建
- 备份方案:若适配严重受阻,可在 M2 降级到 RDK X5,损失可控(主控可二手出)

#### 决策点2: 3D打印机是否购买?

**场景分析**:
- 阶段A需求:结构件打印1次(初版) + 可能返工1-2次
- 阶段B需求:结构件迭代频繁(估计5-10次) + 外壳美化 + 可能的机械臂支架

**候选方案**:

| 方案 | 成本 | 时间成本 | 质量 | 决策 |
|---|---|---|---|---|
| 外包打印(本地) | 1200元/次 × 3次 = 3600元 | 等待3-5天/次 | 中等 | ❌ |
| 购买 Bambu A1 | 一次性2000元 | 即时 | 高(可调优) | ✅ **推荐** |
| 购买拓竹 P1S | 一次性4500元 | 即时 | 更高 | ⚠️ 预算紧张时不选 |

**最终决策**: **购买 Bambu A1**
**调整后预算**:
- Orin Nano 3500元 + Bambu A1 2000元 = 5500元(大件)
- 剩余 4500元 分配给舵机、传感器、杂项
- 结构件打印成本从外包1200元降至耗材200元

**新的阶段A总预算**: 5500(大件)+ 1560(舵机)+ 500(传感器电源)+ 400(杂项工具)+ 800(云资源)+ 240(打印耗材)= **9000元**
**余量**: 1000元

### 3.5 阶段A的"耦合点"清单(确保资产复用)

这些是阶段A必须做扎实的基础工作,直接决定阶段B的启动速度:

| 耦合点 | 阶段A必须做的 | 阶段B如何复用 |
|---|---|---|
| **主控生态** | Jetson Orin Nano 环境配置、CUDA/TensorRT 流程熟悉 | 升级 NX 时,工具链 0 重构 |
| **仿真栈** | 自己修改过 URDF(至少一次结构改动) | 阶段B设计上肢时,URDF建模是日常工作 |
| **域随机化** | 标定 STS3215 的真实摩擦、延迟、回程间隙参数 | 阶段B切准直驱后,标定流程一样 |
| **控制循环架构** | 写干净的 `IMU→policy→servo` 控制环(C++或Python,模块化) | 阶段B加视觉/语音时,往这个架构上插模块即可 |
| **数据采集** | 所有真机运行数据落盘(传感器、舵机、策略输出) | 阶段B训 VLA/imitation 时,这就是种子数据 |
| **CAD流程** | 学会从 Onshape 导出 URDF,并理解关节坐标系 | 阶段B自己设计外壳/上肢时直接复用 |

## 五、关键技术深度说明

### 5.1 Sim2Real Gap 的系统化处理

**Gap 来源分类**:
1. **物理参数误差**: 摩擦系数、质量分布、惯性张量
2. **执行器差异**: 舵机延迟、死区、非线性响应
3. **传感器噪声**: IMU 漂移、足底压力不准
4. **未建模动态**: 线缆拉扯、螺丝松动、温漂

**缩小 Gap 的策略**:

| 策略 | 实施方法 | 成本 |
|---|---|---|
| **域随机化** | 仿真中随机化摩擦、质量、延迟 | 0元(训练时间+20%) |
| **真机标定** | 悬空测试每个舵机的频率响应曲线 | 10小时人力 |
| **特权学习** | 训练时用真实物理参数,推理时用估计值 | 需支持此框架(Isaac Gym支持) |
| **硬件升级** | 关键关节换准直驱 | 8000元 |
| **迁移学习** | 先在仿真训到90%成功率,再用少量真机数据微调 | 100条真机轨迹 |

**阶段A重点**: 域随机化 + 真机标定
**阶段B重点**: 硬件升级 + 迁移学习

### 5.2 VLA 模型选型与训练策略

**候选架构对比**:

| 模型 | 参数量 | 训练数据需求 | 推理速度(Orin Nano) | 开源 | 推荐度 |
|---|---|---|---|---|---|
| OpenVLA | 7B | 100+ demos | ~1-2 FPS | ✅ | ⭐⭐⭐⭐ |
| RT-2 | 55B | 1000+ demos | < 0.5 FPS | ❌ 仅论文 | ⭐⭐ |
| 自训小模型(基于 LLaVA-1.5) | 3B | 50+ demos | ~5 FPS | ✅ | ⭐⭐⭐⭐⭐ |

**推荐路径**: **自训小模型(LLaVA-1.5 微调)**

**理由**:
- 数据需求低(50条高质量遥操作轨迹即可起步)
- 推理速度快(满足实时性要求)
- 可控性强(完全理解架构,方便调试)

**训练数据采集方案**:
1. **M11 前置准备**: 用手柄遥控机器人,录制 RGB + 关节位置序列
2. **标注**: 每条轨迹标注自然语言指令(如 "把红色方块放到蓝色碗里")
3. **数据增强**:
   - 视角旋转(±15°)
   - 光照变化
   - 背景替换
4. **训练**: LoRA 微调 LLaVA-1.5 的视觉编码器,输出动作序列
5. **验证**: 先在仿真里测试,再真机验证

### 5.3 长期记忆系统架构

基于用户已有的 NeuroMemory 项目经验,这里给出针对陪伴机器人的定制方案:

**三层记忆结构**:

```
┌─────────────────────────────────────────────┐
│ L1: 工作记忆(板载 SQLite)                    │
│  - 当前对话上下文(最近10轮)                   │
│  - 实时传感器数据流                          │
│  - 保留时长:24小时,自动清理                  │
└─────────────────────────────────────────────┘
                    ↓ 每晚同步
┌─────────────────────────────────────────────┐
│ L2: 情景记忆(Qdrant 向量库)                  │
│  - 重要对话片段(带情绪标签)                   │
│  - 用户偏好总结                              │
│  - 检索:相似度搜索 + 时间衰减                 │
└─────────────────────────────────────────────┘
                    ↓ 关系抽取
┌─────────────────────────────────────────────┐
│ L3: 语义记忆(Neo4j 知识图谱)                 │
│  - 用户画像节点(姓名、年龄、职业...)          │
│  - 关系边(家庭成员、朋友、宠物)               │
│  - 事件节点(生日、纪念日、重要事件)           │
└─────────────────────────────────────────────┘
```

**与 Claude API 的集成**:
```python
# 每次对话时
relevant_memories = qdrant.search(current_query, top_k=5)
user_graph = neo4j.get_user_subgraph(user_id)

context = f"""
你是一个家庭陪伴机器人,名叫小鸭。

用户画像:
{user_graph}

相关记忆:
{relevant_memories}

当前对话:
{current_conversation}
"""

response = anthropic.messages.create(
    model="claude-sonnet-4-20250514",
    system=context,
    messages=[{"role": "user", "content": current_query}]
)
```

**隐私保护**:
- 所有记忆数据本地加密存储
- 云端同步使用用户自有的 Cloudflare Tunnel(已有 zqxbase.com)
- 敏感词过滤(儿童模式)
